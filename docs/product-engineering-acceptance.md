运行时测试把安装包交给真实的 `dsh plugin --profile web add`，启动独立临时 profile，用 Web 启动链接取得会话 cookie。脚本使用两个临时工作区和一个回环模拟模型，关闭本次测试的日志上传与遥测，并在退出时清理进程和临时目录。

## 浏览器复测

1. 将安装包安装到一个隔离的 DSH Web profile 并启动 Web。用启动时打印的地址打开应用，在侧边栏进入「产品交付台」。
2. 新建一个测试项目，记录目标。编辑目标并刷新，检查新值仍在。
3. 添加项目简报，推进到设计。添加实施计划，推进到构建。
4. 记录一条文字证据和一个有两个选项的决策。检查发布准备出现待决事项，再选择其中一个选项，填写理由并保存。
5. 打开交付检查，使用证据通过一项检查。修改产物后重新查看该项，应看到失效状态。下载 Markdown 或 JSON 并检查选择、理由和检查状态。
6. 从技能库搜索 `pe-start-here`，确认标记为由用户启动。打开会话草稿，确认首行有该技能命令，草稿内容保留项目上下文。
7. 在宽屏和窄窗口中核对导航和表单，检查宿主浅色、深色主题及长文本输入。

## 已观察的浏览器行为

在真实的隔离 DSH Web 中，从侧边栏进入产品交付台并创建项目。保存带换行的简报后，修订号由 1 更新为 2。确认从发现推进到设计后，修订号更新为 3，页面显示新的下一步。技能库打开新的 DSH 会话草稿，首行是 `/pe-app-lifecycle`，并带上项目编号、修订号与读取项目的提示。切换到中文后，工作台及技能库使用中文。搜索「竞品」显示两个匹配结果。

最终安装包的浏览器复测创建了独立测试项目。通过界面登记文字证据并处理决策后，宿主读回的项目包含一条报告型证据和一个已决定事项。

浏览器中的 Markdown 下载按钮已显示；下载事件等待被中断，未取得浏览器下载完成回执，因此不将该步骤记为通过。JSON/Markdown 报告生成内容和状态已经通过真实宿主 API 测试。草稿保留经过独立客户端测试与源码核查；DSH 侧栏会隐藏非当前的空白会话，本次不声称通过界面重新打开并核实了旧草稿。

本次运行和交互覆盖 macOS 的 Web profile。Desktop 界面和其他操作系统需单独验证。回环模型响应只用于驱动 DSH 的请求和工具调用。真实模型的研究、评审质量与第三方服务调用需要各自的运行证据。
