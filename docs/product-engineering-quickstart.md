# Product Engineering · 五分钟验收

本机安装包：`dsh-product-engineering-0.2.0.tgz`。

## 安装

本机已安装 DeepSeek Harness，可直接使用应用附带的 CLI，无需先把 `dsh` 加入 PATH：

```sh
"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh" plugin --profile desktop add "/absolute/path/dsh-product-engineering-0.2.0.tgz"
```

安装后重新启动对应 DSH 窗口。Web 用户将 `desktop` 换成 `web`，重启对应 Web 进程。下载到其他位置时，将命令末尾替换为安装包的实际绝对路径。

## 验收操作

1. 在 DSH 侧边栏添加或打开一个工作区，进入「产品交付台」。
2. 新建项目，例如「个人开发者发布助手」，填写目标并选择工作区。
3. 打开技能库，搜索「产品提案」或「竞品」，点击「打开会话草稿」。应进入带技能命令、项目编号和上下文的新会话；点击发送后由当前 DSH 模型执行。
4. 回到工作台，在产物编辑器选择从文件导入，填写如 `docs/brief.md` 的工作区相对路径。保存后核对正文及关联的文件快照。概览中的下一步应变为「推进到设计」，确认后阶段与修订号更新。
5. 修改刚导入的文件后刷新工作台，在证据区应看到旧快照已失效；重新导入或重新采集只更新材料，不会自动通过检查。
6. 在决策区添加选项并记录选择。交付检查的修复计划应按实际阻塞列出动作；检查项可打开会话草稿，待决事项交由用户处理。
7. 导出 Markdown，核对证据有效性和修复行动。通过检查仍需要关联依据，豁免需要填写理由。

文件快照仅证明登记时的文件内容。对应文件或产物变化后，已通过的相关检查会要求重新审查。文字、链接和命令记录标为报告信息，不会伪装成独立执行结果。

也可从原生会话第一行直接启动：

```text
/pe-start-here 我准备做一个供独立开发者使用的发布助手。先帮我明确目标用户、关键痛点和首版范围。
```

## 验证范围（区分版本）

- 0.2.0：27 项测试在两个 Node 版本通过，最终安装包通过真实 DSH headless 的安装、原生注册、导入、权限、导出、重启与卸载验证。

- 0.1.0 的历史记录：10 项本地测试和 7 组真实 DSH Web 运行时验收通过。0.2.0 的本轮结果见验收记录，不沿用旧包结论。
- 真实页面已验证中英文切换、项目创建、产物保存、阶段推进、证据登记、人工决策、技能搜索和会话草稿跳转。
- 测试版本为 macOS DSH `0.2.1-rc.2`。Desktop 专项、其他系统、真实模型任务效果及第三方服务仍需各自验证。
- JSON/Markdown 报告生成通过宿主测试；浏览器下载完成回执未取得。
